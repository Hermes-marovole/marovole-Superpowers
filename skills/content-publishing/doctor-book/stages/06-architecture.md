# 阶段 6：architecture 全书结构

目标：确定三幕结构、章节顺序、每章章型和字数预算，以及概念、病例、作者故事在全书的分布。

先读：`references/architecture.md`（全文）、`references/chapter-template.md`、`references/atlas/` 里三本样书文末的“全书汇总表（速查）”一节（只读这一节）。

## 步骤

1. 按 `references/architecture.md` 的比例搭三幕。三个部分的比例都按**正文**（只算章节，不含前言、结语、附录）计算，和 `book_check.py` 的口径一致：
   - 第一部分 问题与框架：占正文 12–20%，2–3 章
   - 第二部分 机制与疾病：占正文 30–40%，4–6 章
   - 第三部分 方法与工具：占正文 45–58%，4–6 章
   - 前言、结语、附录另算，合计约占全书 10–15%（前言 3–5%，结语 2–4%，附录 4–8%）
2. 排序规则：先拆旧解释 → 给记分牌（读者能自测的指标）→ 给杠杆（方法）→ 给执行系统（计划和工具）。长章后面接一个短章。
3. 每章写：章号、部分、章名（记忆点 + 冒号 + 承诺收益的副标题）、章型（argument / disease / tactic / bridge / essay / plan）、字数预算（单章 5000–12000 字；bridge 和 essay 章可以短到 3500 字）、一句话论点、主病例、作者故事、引入或复现的概念、可带走物。
4. **概念复现表**：每个命名概念至少出现在 3 章。
5. **病例分配表**：每章一个主病例（C 编号或"情景示例"）；同一个 C 最多做一次主病例；全书开场的人物在结语回收（首尾闭环）。
6. 预算合计（含前言、结语、附录）必须在 `target_chars` 的 ±5% 内。
7. 写 `05_architecture/outline.md`（格式见 `templates/outline.md`），并把每章写进 `state.json` 的 `chapters`：`{"01": {"title": "...", "type": "argument", "budget": 7000, "status": "pending"}}`。

## 自检

- 只看章名，读者能不能看出"问题 → 原理 → 方法"的推进？
- 第三部分的篇幅是否最大？
- 是否每章都有一个具体的人？
- 有没有两章在讲同一件事？

## 完成标准

`outline.md` 各表齐全，预算合计在目标 ±5% 内，自检全部为"是"。把 `stages.architecture` 改为 `done`。
