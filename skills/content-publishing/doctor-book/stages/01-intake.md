# 阶段 1：intake 素材入库

目标：把用户给的所有素材变成可检索的纯文本，登记清单，判定素材等级。

## 步骤

1. 列出 `00_inputs/` 下所有文件，逐个转成 UTF-8 文本，放到 `00_inputs/text/<原文件名>.txt`：
   - PDF：`pdftotext -layout`；没有 pdftotext 就用 python 读取。
   - docx / epub / html / odt：`pandoc -t plain`。
   - md / txt：直接复制。
   - 音频、视频：如果环境里有转写工具（如 whisper）就转写；没有就在清单里标为"未转写"并写入缺口。
   - 图片：有 OCR 工具就识别，否则标为"未处理"。
2. 隐私扫描：对每个文本跑正则，查 18 位身份证号、11 位手机号、"住院号/门诊号/病案号"后跟数字、"床"前的数字。命中的内容在 text 副本里替换成 `＊＊＊`，并在清单里记录"已脱敏 N 处"。原件不动。
3. 写 `01_materials/inventory.md`（格式见 `templates/inventory.md`）：每份素材一行，记录类型（访谈 / 文章 / 讲座稿 / 视频口播稿 / 病例 / 简介 / 其他）、字数、主题、可信度（医生本人原话 / 他人整理 / 公开资料）。
4. 判定素材等级，写入 `state.json` 的 `material_level`：
   - **A**：医生本人的文章、访谈、讲稿合计 ≥ 3 万字，且脱敏病例 ≥ 8 个。
   - **B**：合计 ≥ 8000 字，或病例 ≥ 3 个。
   - **C**：只有专科、主题和简介，或者素材更少。
5. 在 `state.json` 的 `notes` 里写下等级判定的依据和所有缺口。

## 素材等级对后续阶段的影响

- A：病例和作者故事全部来自素材，情景示例只作补充。
- B：主病例优先用素材；不够时，用标注为"情景示例"的典型场景补，每章最多 1 个。
- C：全书病例都是情景示例；作者经历只写履历里能核实的事实，其余放 `【待核实】`；交付报告里明确提示"本书需医生大量补充真实素材"。

## 完成标准

`00_inputs/` 里每个文件都在清单中有一行，状态是"已转文本"或写明了未处理原因；`material_level` 已写入。把 `stages.intake` 改为 `done`。
