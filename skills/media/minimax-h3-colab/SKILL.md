# MiniMax H3 on Colab G4 (RTX PRO 6000 Blackwell 96GB)

Goal: 768p 24fps video+stereo audio from text / first-last frame (FL2VA) / multi-shot reference (Ref2VA) on the user's Colab (Gemini Ultra CU), defaulting to `--gpu G4` (96GB GDDR7 RTX PRO 6000 Blackwell, ~8.71 CU/h; replaces A100). Tooling: `~/HermesWork/colab-h3/h3.sh` (ComfyUI headless) and `~/Workspace/playground/colab-ultra-workstation` (v2.2 90s NVMe launcher + multi-shot Ref2VA workflows).
Success: mp4 in ~/HermesWork/colab-h3/outputs (synced to the operator's Google Drive `MyDrive/colab-h3/outputs/`; the account email and share link stay in local config, never in this repo), verified with ffprobe (h264 + aac 2ch) and a frame check; VM stopped afterwards (`Active assignments: 0`).
Stop: never leave a VM running (`./h3.sh down` or `colab_meter.py stop`, ~8.71 CU/h on G4).

## Commands (dir ~/HermesWork/colab-h3, see README.txt)
- `./h3.sh up` -> G4 96GB Blackwell VM (`colab new -s "$S" --gpu G4`, no `--high-mem` flag needed on G4); mounts Drive (`colab dfs mount` if `colab-dfs-ext` is configured, else `colab drivemount` with ego-browser OAuth). Starts ComfyUI with `--highvram --disable-mmap --fast` so the full ~42–52GB stack stays pinned in 96GB VRAM (0s reload from run #2 onward).
- `./h3.sh gen "prompt" [--seconds 5] [--ratio 9:16] [--turbo] [--first img] [--last img]`
- `./h3.sh down`

## G4 vs A100 & Advanced Workstation (`~/Workspace/playground/colab-ultra-workstation`)
- **Always use G4 (`--gpu G4`, RTX PRO 6000 Blackwell 96GB GDDR7, `sm_120`) instead of A100**: G4 provides 96GB VRAM (+16GB over A100-80GB) and native Blackwell FP8 / NVFP4 acceleration (`Qwen3-VL-32B-Heretic-MiniMax-H3-NVFP4` 14.1GB + `Minimax-h3_Singularity_ref2va_Pruned_v1.3_int8` 19.2GB).
- **Zero-Burn Pre-staging**: Prepare all static keyframes (`1344x768` / `768x1344`) and prompt JSONs locally on Mac (0 CCU) BEFORE starting G4.
- **Fast NVMe Boot (`scripts/launch_g4_comfyui_fast.py` v2.2 & Zero-Drive HF Direct Staging)**: Never symlink `/content/ComfyUI/models` directly to `/content/drive` FUSE (`mmap` drops to ~25 MB/s = 28 min stall) or `rsync` 3,000+ small `.py` files across FUSE (60s+ stall). Pull weights into local NVMe (`/content/fast_models` or `/content/ComfyUI/models`) via HF CDN / Drive v3 API (`aria2c -x 16 -s 16 -k 16M`, ~289–463 MB/s), unpack custom nodes from a single `custom_nodes_bundle.tar.gz` (1.5s), and launch ComfyUI with `--highvram --disable-mmap --fast`. If Google OAuth prompts for a passkey or Drive is not needed for input staging, bypass `colab drivemount` entirely: pull the 41.56GB `scheme_a` weights + custom nodes directly from HuggingFace/GitHub into `/content/ComfyUI/models` via `aria2c -x 16` (~147s), upload input assets to `/tmp/` via `colab upload`, and pull output MP4s back via `colab download`.
- **Dual-Track CCU Accounting (`scripts/colab_meter.py`)**: Always invoke `colab_meter.py` with the `google-colab-cli` uv virtualenv interpreter (`~/.local/share/uv/tools/google-colab-cli/bin/python scripts/colab_meter.py {start|stop} -s <session> -g G4`) — system Python lacks the `colab_cli` package and silently fails to read balance or unassign endpoints. Before `colab stop`, verify any large files written to `/content/drive` have flushed from local DriveFS cache to cloud via Drive v3 API (`files.list`).
- **Colab CLI execution syntax**: `colab exec -s <session>` has no `-c` flag; pass inline code via stdin (`printf "import subprocess; ..." | colab exec -s <session>`) or `-f <script.py>`.
- **Local Acoustic-Aligned Subtitles (`workflows/01_dialogue_2p_photorealistic/auto_subtitle.py`)**: Expects segments named `<root>/<seg_prefix>_Seg01.mp4` (`--root`, `--seg-prefix`, `--master`, `--out`, `--srt`). When running on a single test segment, pass `--lines "单段台词"` so `len(script_lines) == 1` instead of the 4-segment default in `drama_config.json`.
- **Multi-shot Ref2VA & Continuity Rules (when running multi-segment dialogue/action via `colab-ultra-workstation`)**:
  1. **Photorealism**: Add `minimax-h3-realism-people.safetensors` (`0.75`, trigger `r34l1sm`) + `minimax-h3-facial-realism-closeup-cp2000.safetensors` (`0.50` for dialogue, `0.15` for action/combat).
  2. **Voice consistency without TTS robotic tone**: Extract H3's own native speech from Seg 1/2 (`ffmpeg -af "aresample=32000,pan=stereo|c0=c0|c1=c0"`) as `<Audio 1>` seed (`Self-Anchor Voice`); pass ONLY the active speaker's `<Audio 1>` per segment (Speech-Active Gating); for shouting/outbursts, add paralinguistic prefix + a `00:00.400` transient sound cue in `overall_soundscape` (`T8mars` protocol).
  3. **Defogging multi-segment joins**: Set `MiniMaxH3JoinMatch` explicitly to `tuning="manual", strength=0.35, min_excess=2.5, match_spread=False, match_detail=False` (default `auto` compresses spread by ~31.8%, causing gray fog on Seg 3/4).
  4. **Side-profile & camera lock (`V9_TailLock`)**: Avoid plural facial nouns (`eyes`, `brows`) and negative camera phrases (`without turning toward the camera`) on 90° profile shots; use a pure 90° profile reference image `<Picture 1>` and pin two `MiniMaxH3AddGuide` nodes at tail latent steps (`frame_idx=107` and `136`).
  5. **5MB Latent Hot-Resume (`H3SaveAVLatent` / `H3LoadAVLatent`)**: Save raw `AV_LATENT` (`~4.8MB`) per segment to Drive so re-rolling a single middle segment (`--only-seg N`) takes ~3 min instead of re-running all segments.

## Runtime & Region Rules
- VM region must be outside license-excluded US/EU/UK/KR (e.g., `asia-southeast1` / `ass1`). Verify the assigned endpoint via `colab sessions` right after `colab new`; if Colab allocates an excluded region (such as `euw4` in Europe or `us-*`), immediately `colab stop -s <session>` and re-run `colab new` until an Asia endpoint (`ass1`/`ase1`/`ane1`) is assigned.
- **`colab sessions` line shape (inspect one real line before writing any region filter)**: the line is `<session_name> gpu-g4-s-<region><n>-<suffix> | Hardware: G4 | Shape: Standard | Variant: GPU` — the region code lives inside the `gpu-g4-s-…` token (`use5a2`, `usw4a1`, `euw4…`, `ass…`, `ase…`, `ane…`), NOT in an `m-s-…` / `Hardware:` field. A retry loop grepping for the wrong prefix (e.g. `m-s-[a-z0-9]+-(ass|ase|ane)`) never matches, so it stops every allocation including good ones and burns the whole loop. Print one line from a live session and build the regex from it.
- **Region-retry loops destroy uploaded files**: `colab stop` tears down the VM and everything on `/content`, so the loop must finish BEFORE any `colab upload` / `bootstrap` / `nohup` launch. Order: allocate → confirm region → upload inputs + scripts → bootstrap → launch batch. If a stop happened mid-setup, the next `colab upload` fails with `Session '<name>' not found` because the session record is gone too — recreate the session and re-upload from scratch, never assume partial state survived.
- 5s clip: standard 20 steps ~365s (17s/step) on A100, turbo 8-step LoRA ~160s; on G4 with `Singularity v1.3` + `NVFP4`, 10–12 step full reference takes ~79–121s with 0s model reload after run #1.
- **I2V (first-frame only) on G4, pruned bf16 FL2VA without the turbo LoRA**: `--turbo --steps 12 --first kf.png --seconds 5 --ratio 16:9` runs ~10.6s/step ≈ 2min per clip; `minimax_h3_fl2va_pruned_bf16.safetensors` loads 38.45GB once (`full load: True`) and stays pinned, so shot 2 onward starts sampling immediately. Budget ~2min/shot when planning a 9-shot book (≈18min total) — and expect `colab exec` polling to hit its 90s timeout mid-sampling, so the local monitor needs the retry wrapper.
- Chinese dialogue in quotes is spoken correctly (whisper-verified). H3 may burn in subtitles -> add 无字幕 if unwanted. Turbo can show color blotches; standard for finals.

## Pitfalls
- `colab exec`, `colab upload`, and `colab download` occasionally fail with `"Connection was lost"`, `ColabRequestError`, or `subprocess.TimeoutExpired` when the VM is under heavy GPU/disk load -> wrap all three in retry loops with `timeout>=90` and catch `Exception` (including `TimeoutExpired`). Before starting a batch, run `colab sessions` to check for `[?] <endpoint>` orphan VMs left behind when a previous `colab new -s h3` overwrote `~/.config/colab-cli/sessions.json` without stopping the old runtime (which doubles burn rate); if an `[?]` entry exists, temporarily register its endpoint under a dummy key in `sessions.json` and run `colab stop -s <dummy>` to terminate it. For long jobs, launch with `nohup bash -c '<cmd> || echo REMOTE_FAIL' > /content/<job>.log 2>&1 &` on the VM and poll for `^DONE` or `^REMOTE_FAIL` — never grep poll output for generic `Traceback`, because a local `colab exec` failure prints a local CLI traceback on stderr and falsely kills a running ComfyUI job.
- Unattended multi-hour batch runs (`run_batch.sh`): isolate the Colab session name via `export H3_SESSION=<batch_name>` (e.g. `h3_batch3`) before `up` and `run_batch.sh` — other concurrent sessions default to `-s h3` and will overwrite or stop the shared `h3` session mid-batch, causing `h3.sh` to poll a missing `/content/<prefix>.log` forever without mounting `/content/drive`. Interactive one-off H3 use (experiments, single renders) must also export a unique `H3_SESSION` — a bare `h3` session resets the env out from under a running batch. Guard the `h3.sh gen` polling loop with a consecutive-empty-log counter (`_empty >= 10`) and a wall-clock timeout (`>= 1200s`) that exits non-zero when `vm "cat /content/$PREFIX.log"` returns empty — if `vm()` swallows `colab exec` errors and returns 0 with empty stdout after Colab reclaims an idle/disconnected VM (e.g. during macOS sleep), an unguarded loop prints `...` forever without failing or advancing. Strip `\r` when reading prompt files from external packages (`tr -d '\r' < "$prompt"`), brace-delimit shell variables immediately followed by CJK punctuation (e.g. `${id}（...` rather than `$id（...` — under `set -u`, bash merges the leading byte of `（` into the identifier and aborts the batch on the first failure branch with `unbound variable`), and chain a second idempotent pass followed by automatic teardown (`bash run_batch.sh && bash run_batch.sh; bash tool/h3.sh down`) inside a `persist_on_release=true` background job so the G4 VM shuts down immediately when finished. When unpacking a new colleague handoff archive (`移交-*.zip`), extract with Python `zipfile` decoding non-UTF8 (`flag_bits & 0x800 == 0`) filenames via `encode('cp437').decode('gbk')` (macOS `unzip` mangles Windows GBK Chinese filenames so `manifest.json` paths fail), and always overwrite the package's bundled `tool/{bootstrap_vm.py,h3.sh}` and `run_batch.sh` with the hardened versions from the previous batch before running `up` — colleague packages re-bundle the unhardened template that copies 70GB over slow Drive FUSE and lacks retry/CRLF/dead-VM guards.
- **Zero-idle-burn batch from pre-approved keyframes**: upload all keyframes + a `shots_meta.json` + one remote `run_*.py`, launch it with `nohup python -u /content/run_*.py > /content/batch_<tag>.log 2>&1 &`, then run a LOCAL monitor that polls `cat /content/batch_<tag>.log` and, on each `SHOT_DONE_<id>`, immediately `colab download` that mp4 — and `colab stop` the instant the last clip lands, doing the ffmpeg assembly locally at 0 CU. Models load once (`loaded completely … full load: True`, ~38 GB on the FL2VA pruned bf16) so shot 1 pays the load and every later shot starts sampling immediately.
- ComfyUI API: SaveVideo format="auto", codec="auto"; length must be 17k+5 frames (124 = 5s).
- 2K / H3-Context-IR are NOT open; only via MiniMax paid API.
- Drive restore path on a fresh VM: copying 70GB of weights over Google Drive FUSE (`cp /content/drive/...`) throttles at ~35 MB/s (>30 min), whereas downloading directly from HuggingFace (`hf_hub_download('Comfy-Org/MiniMax-H3', ...)`) or via `aria2c -x 16` against HF CDN + Drive v3 API finishes in ~1.5–2.5 minutes. Prefer direct HF / Drive v3 API download into local NVMe, and keep `/content/drive` FUSE only for backing up generated output MP4s.
- Account GPU entitlement: `--gpu H100` is rejected on this Colab tier; default to `--gpu G4` (96GB RTX PRO 6000 Blackwell, no `--high-mem` needed; `--gpu A100 --high-mem` is legacy fallback only).
- Public posts must disclose AI generation (license AUP #12); also show "MiniMax H3" credit.
- Drive mount OAuth automation: do not ask user to click manually. Use `colab dfs mount` if `colab-dfs-ext` is installed (when running `colab dfs consent` for the first time, explicitly check the unchecked-by-default Google Drive scope checkbox on the OAuth screen, or mounting fails with `403 ACCESS_TOKEN_SCOPE_INSUFFICIENT`). Otherwise use ego-browser to navigate the Google OAuth URL, call `await page.snapshot()` before each step, and click `role:button[name='Continue']` (or `'Allow'`) rather than hardcoded `ref=N` numbers (which fail with `Unknown ref` across fresh snapshots or account states) to reach the ephem success screen. If `colab drivemount` exited with `ValueError: mount failed` during auth propagation, simply re-run `colab drivemount -s <session>` right after — it detects the cached credential and mounts `/content/drive` cleanly.
- `h3.sh gen` stdout can contain non-UTF-8 bytes: wrap with subprocess(..., text=True, errors="replace"). Set `H3_PREFIX` env for deterministic output names.
- Side-view / seated actions: H3 rotates the subject/prop mid-clip whenever first and last keyframes disagree in orientation (e.g. front-facing sit → side leg-raise), because it interpolates the turn. Make BOTH keyframes pure 90° side, measure shoulder-projection width with a pose estimator (pure side ≤0.005 of frame width, front ≈0.07) before generating, and add a fixed side-camera prompt. Never reuse a front-facing take and hope it stays side.

## Character / choreography workflow
- Make one character ref with gpt-image-2 (Dogbooks), then pose keyframes via /v1/images/edits using the ref + official movement cues; center-crop to 768x1344.
- **Anti-drift keyframe triad (from `ai-story-video-director`)**:
  1. **Reverse keyframe order**: draw the densest frame first (usually the **tail frame**), then derive the **head frame** from the tail frame so camera pose and background geometry stay 100% locked.
  2. **Code-cropped push-in**: for slow push-in shots, crop and upscale the head frame in code to create the tail frame (never re-generate the tail frame with AI or keep head==tail).
  3. **Patch-back local edits & diff gate**: `/v1/images/edits` re-encodes the entire image and subtly shifts background walls/props; paste only the edited bounding box back onto the original image (`precheck_keyframes.py patch`) and run `precheck_keyframes.py diff` before starting G4 so untouched background pixels have zero drift.
- Generate each shot FL2V with first=pose A, last=pose B; chain shots so clip N's last keyframe = clip N+1's first -> seamless joins (drop the duplicate frame).
- Prompt: fixed camera, 无字幕无任何文字, slow even motion; H3 audio is discarded. Check every clip with a 0.5 s contact sheet; fix wrong end poses by regenerating the keyframe (e.g. arms not fully straight), not the prompt.
- Exercise / follow-along course videos (action libraries, reps×sets, countdown UI, per-move cue audio, two-shot A→B/B→A looping, primitive dedup, turbo-then-standard): follow the `exercise-follow-along-video` skill — it owns the full pipeline, assembly script and QA checklist.
- Final upscale filter (9:16): `scale=1080:1920:flags=lanczos,unsharp=5:5:0.4,format=yuv420p`.
- Example pipeline: ~/HermesWork/灵知营养短视频/opus-video/baduanjin-4/{h3/run_batch.py,build_h3.py,render_overlay.py}.

## Hybrid digital-human course recording workflow (`~/HermesWork/course-avatar-workflow`)
For lecture / training courses where an AI instructor replaces on-camera recording, decouple voice from video and split the timeline across three tracks (`anchor` 20% fullscreen instructor, `board_pip` / `board` 70% Playwright HTML/SVG courseware, `broll_h3` 10% MiniMax H3 visual demonstrations) rather than rendering a full-length talking-head video:
- **Pipeline entry**: `python3 ~/HermesWork/course-avatar-workflow/course_workflow.py build <lesson_dir>` reads `<lesson_dir>/lesson.json`, runs one-shot ElevenLabs TTS (`with-timestamps`) for continuous prosody and zero-typo SRT subtitles, slices out `audio/avatar_<beat_id>.wav` only for `anchor` and `board_pip` beats (saving 50–75% avatar compute), renders the transparent/opaque `1920x1080` UI + slide overlay (`slides_template.html` via `window.render(t)`), and composites all tracks with `-14 LUFS` loudness normalization plus a 2×2 QA contact sheet (`qa/contact_sheet.jpg`).
- **Avatar backends**: use Chanjing OpenAPI (`1 bean/s`), Shanjian bare-video API (`0.75 credits/s`), or open-source `EchoMimicV3-Flash` / `Sonic` on the same Colab G4 ComfyUI VM (`python3 ~/HermesWork/course-avatar-workflow/colab_avatar_addon.py setup`).
- **FFmpeg circular PiP performance & layout pitfalls**:
  - Apply the per-pixel circular alpha mask (`geq`) to the short (~5 s) base avatar clip *before* `-stream_loop -1 -c:v copy` — running `geq` after looping across a full lesson multiplies encode time by 10× and risks command timeouts.
  - Keep the UI/slide overlay (`ui_overlay.mov`) *below* the circular PiP stream (`pip_circle`) so opaque board backgrounds (`board_pip` mode) do not cover the avatar, and position the `280x280` circle at `x=1572,y=578` so its bottom edge (`y=858`) sits cleanly above the instructor nameplate pill (`bottom: 162px`) and subtitle safe zone (`y>=935`).
