## TL;DR

- **单入口总导演编排**：以 Claude Code（或 Codex）作为唯一交互入口（总导演），通过 CLI 调起 Codex（画师，生成设定图与首尾帧）和火山引擎方舟 API 的 Seedance（动画师，首尾帧生视频），并用 `ffmpeg` + Python 完成色块草图、裁剪、拼接、调色与超分。
- **核心省钱铁律——把错误挡在花钱之前**：「文字改几个字不花钱 → 图重画一张不额外花钱（消耗订阅额度）→ 视频重新生成按秒付钱（Seedance 2.5 720p 约 ¥1.5/秒，2.0 mini 约 ¥0.5/秒）」。能在文字阶段发现的错不留到图上，能在图上发现的错绝不留到视频上。
- **跨上下文盲审机制（Fresh-Context Blind QA）**：主 Agent 聊久了会自动脑补，因此每个关键节点（故事定稿、分镜/首尾帧、提交视频前、成片复核）都必须**新开一个无历史上下文的子 Agent**，只给当前交付物不给前置结论，做纯挑错审核（只读不改，写明“通过/不通过”）。
- **低抽卡率的工程化手段**：采用片段式结构避开接戏穿帮；先画内容最多的尾帧再改出首帧以锁死机位；用代码绘制 1920×1080 黄金比例（38%/62%）色块草图并转黑白查明暗对比；使用标准化的**七段式视频提示词**（画风/镜头/构图与配色/人物/逐秒/声音/约束）与 20 条模型常见翻车修辞对照表。
- **四线程子代理协作模式**：「主做（全流程制作）+ 审核（逐步挑错，生成视频前必须签“通过”）+ 监督（读取历史对话整理要求清单，防遗忘）+ 代理（整理用户偏好，在分歧或预算范围内替用户拍板）」。

## 原帖核心内容

本文聚焦于一个核心问题：**如何依靠一套多模型工作流与实操避坑准则，用尽量少的钱、尽量低的抽卡率，做出一条满意的 AI 视频。**

全文分为两大部分：**工具层（多模型分工与四线程架构）**与**实操层（从想法到成片的 8 步全流程 + 完整 Prompt 模板）**。

### 一、工具层：让 Claude 当总导演，只和它沟通

使用 **3 个模型 + 2 个本地工具**：`Claude Code`、`Codex`、`Seedance`，外加 `ffmpeg` 和 `Python`。

#### 1. 模型与人员角色分工

```
[我] ──(只和 Claude 沟通)──> [Claude 总导演] ──┬──> [Codex 画师]（画设定图、样帧、首尾帧）
                                              └──> [Seedance 动画师]（首尾帧生成视频）
```

| 角色 | 职责 |
| --- | --- |
| **我（人类）** | 选方向、确认画风、批准花钱；看动态、听声音（AI 无法真正感知流畅度与听感） |
| **Claude（总导演）** | 写故事和分镜，写所有提示词，调用其他模型，抽帧放大检查每张图和每段视频，写 Python / ffmpeg 代码做后期（若无 Claude 也可全程用 Codex，作者体感 Claude 更聪明、审美略高） |
| **Codex（画师）** | 画设定图、样帧和每个镜头的首尾帧（支持基于原图的局部修改） |
| **Seedance（动画师）** | 把首尾帧变成几秒钟的视频（通过火山引擎方舟 API 调用） |

#### 2. 核心控费原则：错误越早发现，越省钱

```
[文字：改几个字，不花钱] ──> [图：重画一张，不额外花钱] ──> [视频：重新生成，按秒付钱]
```

- **能在文字里发现的错，不要留到图上；能在图上发现的错，不要留到视频上。**
- 视频发现问题先想能不能裁剪首尾帧或用代码修，修不了才重拍，且必须先改提示词或首尾帧再重拍单镜。

#### 3. 【Prompt 1】总导演初始化提示词（开局发送给 Claude Code / Codex）

```text
你当这支短片的总导演，全程负责，我只和你沟通。
开工前先做两件事：
1. 问我：片长、画幅、总预算、要不要配乐和字幕。
2. 检查 Codex、ffmpeg、Python 和 ARK_API_KEY 能不能用，缺什么告诉我。

记住所有文件都放在一个新的项目文件夹里。

分工：
- 你：写故事和分镜，写所有提示词，调用其他模型，抽帧放大检查每张图和每段视频，用 ffmpeg 和 Python 写代码做后期。
- Codex（画师）：画设定图、样帧和每个镜头的首尾帧。你不自己画。

如果你就是 Codex，就用你自己的生图工具。

- Seedance（动画师）：把首尾帧变成几秒钟的视频。

- 我：选方向、确认画风、批准花钱、看动态、听声音。

调用 Codex：
codex exec --skip-git-repo-check -s read-only -i 参考图.png - < 提示词.txt
提示词开头写：Use your image generation tool to create exactly ONE image. Do not run shell commands.
画好的图在 ~/.codex/generated_images/<日志里的 session id>/。

调用 Seedance：
POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks
key 在环境变量 ARK_API_KEY 里，不要打印出来。请求格式查火山方舟文档。
模型选 doubao-seedance-2-5-260628（720p 约 ¥1.5/秒）或 doubao-seedance-2-0-mini-260615（720p 约 ¥0.5/秒），价格以账单为准。

总原则：把错误挡在花钱之前。文字里能发现的错，不留到图上；图上能发现的错，不留到视频上。

规矩：
1. 我确认故事前，不画任何图。
2. 我确认画风前，不画正式镜头。
3. 提交视频生成前，另开一个 agent 审核提示词和图片的每个细节，它只挑错，不改文件。通过后报价，我同意才提交。
4. 视频有问题，先想能不能用代码修，修不了才重拍，只拍这一镜。
5. 新版本存新文件，不覆盖、不删除旧文件。
6. 你看不到真正的动态，也听不到声音。没看过、没听过的东西，要明确告诉我。
7. 不充值，不买额度。接口返回欠费就停，把已有的片段先粗剪给我看。
```

### 二、从一个想法到完整视频的 8 步全流程

#### 步骤 1：从一个想法到完整剧情（含独立 Agent 盲审）

好故事必须满足 **5 条硬标准**：
1. **符合现实逻辑**：每个转折追问“为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？”
2. **一句话说清主旨**：说不出来说明剧情平淡，必须改。
3. **开头抓人**：最抓眼球的画面放前面，明确第几秒出现什么。
4. **旁人反应像真人（有先后顺序）**：每个包袱或转折按「**问题 → 主角怎么解决 → 旁人什么反应**」三段写。**严禁几个人同一秒做同一个动作**（同一秒一起举手一看就是模型做的；一个接一个有先后、吃惊时身体往后缩才像真人）。
5. **避开 AI 视频模型的天然弱点 & 优选片段式结构**：
   - **9 大必避弱点**：人物交叉、手拿小东西、文字、镜子和倒影、左右不对称的特征、一镜内换光、一人连做三个动作、俯拍看不到脸、配角太多。
   - **故事结构**：首选**片段式**（镜头间不用接戏，最稳）；慎用连贯式（最易穿帮）。

##### 【Prompt 2】剧情撰写与分镜故事展开提示词

```text
我想做的片子：[一句话，或者我的初步剧情]。片长：[秒]。
配歌：[歌名、时长、BPM；不配歌就删掉]。
参考片：[有就写，没有就删掉]。

先帮我把这个想法完善成一个完整的故事。有不清楚的地方就问我，我们一起聊，等我确认了再往下写。
故事结构首选片段式，因为每个镜头之间都不用接戏，最稳。连贯式最容易穿帮，除非我要求，否则不要用。

故事确定以后，展开成逐镜头的故事，要满足下面这些要求：
1. 符合现实逻辑。每个转折都按现实追问一遍：为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？
2. 能用一句话说清想表达什么。先把这句话写出来，说不出来就说明故事还要改。
3. 开头就要抓人。最抓眼球的画面放在前面，写清楚第几秒出现什么。
4. 旁人的反应要像真人。每个包袱或者转折都分 3 段写：问题 → 主角怎么解决 → 旁人什么反应。反应要有先后，不能几个人同一秒做同一个动作。细节也要真实，比如人吃惊时身体会往后缩。
5. 要让 AI 拍得出来。避开这些弱点：人物交叉、手拿小东西、文字、镜子和倒影、左右不对称的特征、一个镜头里换光、一个人连做三个动作、俯拍看不到脸、配角太多。

如果配歌，转折对副歌，关键动作对重拍。
```

##### 【Prompt 3】故事盲审提示词（新开子 Agent，只喂故事定稿，防主 Agent 脑补）

```text
这是一支短片的逐镜头故事。你是第一次看，只负责挑错，不改文件。
1. 只按镜头顺序读，先写出你看懂的故事。
2. 按顺序追问每个转折：为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？
3. 能用一句话说清想表达什么吗？
4. 开头抓人吗？最抓眼球的画面放在前面了吗？
5. 旁人的反应像真人吗？有没有先后？
6. 哪些镜头 AI 视频模型容易拍错？（人物交叉、手拿小东西、文字、镜子和倒影、左右不对称的特征、一个镜头里换光、一个人连做三个动作、俯拍看不到脸、配角太多）
每条写：镜头、问题、建议改法。没把握的写“可能”。最后写“通过”或“不通过”。
```

#### 步骤 2：分镜——定镜头语言、构图和配色

作者认为**构图和配色比剧情更重要**。如果有参考片，直接让 Claude 逐帧拆解参考片的机位和进出画比例；没有参考片则遵循以下 **6 条分镜准则**：

1. **每镜换角度**：全片平视正面最多 2 次，其余用俯拍、仰拍、背后、过肩、透过遮挡物拍。
2. **画面里要一直有东西在动（防“画面死掉”）**：大多数镜头最好有人或物进出画；若人物静坐，必须让环境元素动起来（飘过的纸、身后路人）；固定机位更要让人物在纵深或横向上走动；景别（全身、半身、特写）必须交替变化。
3. **写清每个镜头具体是什么在动**：摄影机、焦点切换、光线变化、前景飘过物、人物微动作（如手抖），至少有一样；同时做到动静对比。
4. **镜头运动要有理由**：① 跟拍（信飞到哪跟到哪）；② 慢推给特写；③ 由近慢拉到远。
5. **每一秒截图都要好看（黄金比例构图）**：人的头或眼睛落在画面从左往右约 **38% 或 62%** 的位置，不要放正中间。
6. **配色单独设计 + 黑白明暗校验**：画第一张图前先列分场色表；用代码生成 1920×1080 色块草图（标出 38%/62% 线），并**转成黑白检查前景人物与背景是否区分得开**，区分不开说明明暗对比不够，必须重调配色。

##### 【Prompt 4】分镜表与代码色块草图提示词

```text
把定稿的故事写成分镜表。每个镜头一行，写清楚：片中时间（配歌就按小节算）、生成秒数（片中时长向上取整，尽量多留 0.5 秒）、景别、机位、运镜、谁往哪走（写画面的左右）、靠什么表情推进、这个镜头是什么在动、怎么转到下一个镜头。

如果有参考片，先逐帧看参考片，把机位、进出画比例这些都量出来，然后学习模仿。没有参考片就按下面的要求自己构思。

要求：
1. 每个镜头换角度。全片平视正面最多两次，其余用俯拍、仰拍、从背后、过肩、透过东西拍。
2. 画面里要一直有东西在动。大多数镜头都要有人或者东西走进画面，或者走出画面。人不走动的镜头，就让别的东西动起来，比如飘过去的一张纸，或者身后走过的路人。固定机位更要让人在画面里走动，比如从远处走到近处。
3. 不要连着好几个镜头都是一样大小的画面，全身、半身、脸部特写要换着来。
4. 每个镜头都要写清楚是什么在动：摄影机、焦点、光线、镜头前面飘过的东西，或者人物的小动作，至少要有一样。也不要一直动，该动的地方动，该静的地方静。
5. 镜头运动要有理由：跟着一个东西走，慢慢推近给特写，或者从近处慢慢拉远。
6. 每一秒截图都要好看。人的头或者眼睛落在画面从左往右大约 38% 或者 62% 的位置，不要放在正中间。

配色要单独设计，在画第一张图之前定好。我想要的配色：[我的喜好；没想好就给我几个方案选]。
把每一场用什么颜色单独列成一张色表。

最后用代码给每个镜头画一张 1920×1080 的色块草图，标出 38% 和 62% 的位置和主要的东西，拼成一张总表给我确认。再把草图转成黑白看一遍，如果人和背景区分不开，就说明明暗对比不明显，要重新调配色。
```

#### 步骤 3：定画风，画设定图

- **定画风**：吉卜力手绘温暖风、剪纸风、写实照片风、美式手绘线条风等，最好直接给 AI 喂参考图。Claude 写 Prompt，Codex 生图，人来拍板。
- **画角色与固定道具设定图**：包含正面、侧面和几个核心表情。**人物身上的固定特征必须写死位置**（例如“纹身在左手臂上”），否则后续每镜位置都会漂移。

---

#### 步骤 4：出每个视频片段的首尾帧图片（降低抽卡率的核心）

- **为什么必须有首尾帧**：纯文本生视频极易出逻辑错误，且雨、帽子、纹身等小物件只靠文字描述经常拍着拍着消失，必须在**首帧和尾帧同时画出来**才稳。
- **5 条作画实操铁律**：
  1. **先写后审再画**：先让 AI 写清每镜首帧画什么、尾帧画什么、中间发生什么，交由审核 Agent 过关后再调 Codex 画，节省生图额度。
  2. **先画尾帧（内容最多），再在尾帧上改出首帧**：保证首尾两张图的摄影机位置和背景构图完全一致。
  3. **同场景同机位直接局部改图**：利用 Codex 的参考图修改能力，不在新图上从零重画。
  4. **推镜头的尾帧直接靠代码裁切首帧放大**：若首尾帧构图完全一样，生成的视频镜头就不会推进；直接将首帧局部裁切放大作为尾帧即可稳定实现推镜。
  5. **尺寸与局部贴回修复**：Codex 出图未必严格 16:9，提交 Seedance 前必须用代码统一裁好并确保首尾帧尺寸一致；此外，**Codex 局部重绘仍会重算整张图，只改局部时应把改好的区域用代码贴回原图**，防止背景其他部分发生微变。

##### 【Prompt 5】首尾帧 8 项放大检查提示词

```text
首尾帧画完了，帮我按下面这些逐条检查，每张图都要放大看。有问题就告诉我是哪张图、哪里不对，我同意了再改。
材料：[首帧]、[尾帧]、[设定图]、[这个镜头的分镜]

1. 动作要用到的东西，首帧里必须有。比如后面要拿杯子，首帧里就要看得到杯子，否则杯子会凭空冒出来。
2. 别人的反应要提前摆好。一段视频就是一个镜头，没法中途切过去拍别人，所以首帧里要安排好：一个人在前面做事，另一个人在后面，脸朝着镜头。
3. 很多人一起出现时，不能摆同一个姿势，不然模型会让所有人同时动。
4. 给动作留出空间。东西要落到、飘到的地方要提前空出来，人的头顶也要留点空。
5. 风往哪边吹要统一，不能围巾往左飘，床单却往右飘。
6. 缩小到手机大小看一遍，远处的人太小、看不清就要改。
7. 放大看有没有多余的东西，比如多一个水壶，或者多一条奇怪的细线。
8. 把首帧和尾帧叠在一起看有没有错位。不该变的地方两张图必须一样。比如墙的颜色不一样，视频里墙就会慢慢变色；杯子大了一点，视频里杯子就会慢慢变大。

要改图的时候注意两点：
- Codex 就算只改一小块，也会把整张图重新处理一遍。所以只改一小块时，要把改好的那一块贴回原图。
- Codex 的额度用完了就等它恢复，不要买额度，也不要一次同时画太多张。
```

#### 步骤 5：写视频提示词，提交前盲审

画面出问题先怀疑提示词。作者总结出固定的**七段式视频提示词模板**与 **20 条模型常见错误修辞对照表**。

##### 【Prompt 6】七段式视频生成提示词模板

```text
【画风】[一句话写画风，比如：干净的现代 2D 手绘动画，平涂色块，线条利落，没有颗粒和纹理]。整段的画风、颜色、人物设计与首帧和尾帧完全一致。
【镜头】整段 [X] 秒，[景别]，[机位]，[运镜；不动就写“不推不拉不摇，不切镜”]。
【构图与配色】[人和东西在画面哪里，墙和光是什么颜色。要和首帧对得上]
【人物】[每个人的长相、衣服、固定道具，写死]
【逐秒】
0–0.2 秒：画面完全静止，和首帧一模一样。
[每一段：谁做什么，表情怎么变，手放在哪、不能碰什么，往画面哪边]
最后 0.3 秒：所有人完全停住，画面与尾帧完全一致。
【声音】只有 [看得见原因的声音]。人物不说话。
【约束】画面里一直只有首帧这几个人和这些东西，脸和身形全程不变，一镜到底。画面干干净净，没有文字、字幕、水印。
```

##### 模型 20 大常见翻车点与有效写法对照表

| 模型容易犯的错 | 应该怎么写 / 怎么处理 |
| --- | --- |
| 一群人同时做同一个动作 | 写清楚谁先谁后：“老爸第一个……过一两秒老奶奶才……小女孩最后……”，首帧也不要摆同一个姿势 |
| 本来该风做的事，人自己动手做了（如邮差用手掀开邮包） | 写清楚原因，再写上“两只手从头到尾都没有碰邮包” |
| 云、月亮、植物长出眼睛和嘴巴 | 不要写“卡通云”，要写“蓬松的灰白色积云，只有棉絮一样的纹理和阴影”，动作也只写它怎么移动 |
| 人往反方向走 | 方向要按画面来写：“朝画面左边走，跨过左边的店门” |
| 一句话有两种意思（如写“窗户后面的老人”，结果车里冒出了人） | 写得更具体：“左上角石头房子的窗口里”，再加上“驾驶座一直空着” |
| 东西的数量变了 | 把数量直接写出来：“只有一封黄信封，之后他怀里全是白信封” |
| 写“不要怎么样”经常没用（如写了“壶嘴不出水”还是出水） | 尽量改成正面的说法：“画面里一直只有首帧这几个人” |
| 模型会自己联想道具的用法（如壶总是出水） | 干脆不让这个道具出现在有动作的镜头里 |
| 东西凭空出现 | 只用首帧里已经有的东西 |
| 东西突然飞走或者瞬间移动 | 写清楚它是怎么动的：“顺着后脑勺往后一滑，接住，扣回头上” |
| 雨、帽子、纹身拍着拍着就没了 | 首帧和尾帧都画上 |
| 闪电画得太写实 | 写“云里闪一下白光”，再把开头剪掉 |
| 一个镜头动作太多就乱了 | 每个镜头只写一两个主要动作 |
| 动作的时间和写的不一样 | 写的时间只能算大概，多留一点时间，后期再用剪辑和变速对上节拍 |
| 镜头推得没有写的那么明显 | 后期让 Claude 用代码再推一点 |
| 人的嘴自己在动 | 写明“人物不说话”，还动就用代码修 |
| 写了“没有音乐”还是混进了音乐（Seedance 2.5） | 片段自带的声音不用，后期另外加 |
| 结尾几帧突然跳到尾帧的样子（Seedance 2.5） | 后期选一张没问题的画面，后面都停在这一张 |
| 第一张画面特别锐（Seedance 2.5） | 直接把这一张去掉 |
| 视频越到后面越暗越冷（Seedance 2.0 mini） | 每条视频都按它自己的首帧把颜色调回来 |

##### 【Prompt 7】提交 Seedance 前的守门员盲审提示词（新开子 Agent）

> 作者实测：这一步曾查出“两张图里的杯子大小差了 13%”、“帽檐一张有一张没有”、“左右写反了”等细节问题，是把抽卡率压到极低的核心秘诀。

```text
你是审核，只读不改。这个镜头马上要提交视频生成，花的是真钱。
材料：[提示词文件]、[首帧]、[尾帧]、[设定图]、[分镜表]、[配色规则]。
逐项核对，放大看图：
1. 提示词的每句话和两张图对得上吗？（位置、左右、颜色、人数、道具数量、衣服、表情）
2. 两张图的机位、大小、背景一致吗？
3. 和设定图、配色规则、前后镜头对得上吗？
4. 动作现实吗？每个动作的原因写了吗？手放在哪？
5. 模型可能在哪里出错？（同时动作、凭空出现、长脸、走反方向、歧义词）
最后只写“通过”或“不通过”。不通过就逐条列出要改什么。
```

#### 步骤 6：生成视频与省钱技巧

- **省钱与选型技巧**：
  1. **720p 生成 + 后期超分**：用 720p 生成，后期再用 `lanczos` 放大到 1080p。
  2. **不拍测试废片**：直接拍第一个正式镜头，能用就赚了；新手法先挑 1–2 个最难镜头试拍。
  3. **Seedance 2.5 vs 2.0 mini**：2.5 价格约为 2.0 mini 的 3 倍（720p 约 ¥1.5/秒 vs ¥0.5/秒）。非高难度复杂镜头用 `2.0 mini` 完全够用。
  4. **音效取舍**：`2.0 mini` 自带音效常可直用；`2.5` 即使写明“无音乐”也常混入 BGM，建议弃用自带音轨、后期另配。
- **废片抢救三步法（不轻易重拍）**：
  1. **能不能剪掉**：开头或结尾几帧跳变/过锐，直接掐头去尾。
  2. **能不能用代码修**：如推镜不够、颜色变暗冷、嘴部乱动，先让 Claude 写脚本修复。
  3. **改后重拍且保留旧素材**：必须重拍时先改 Prompt 或首尾帧；旧片段绝不删除，最后一起比选混剪。

#### 步骤 7：拼接、转场、调色、放大（纯代码后期）

##### 【Prompt 8】代码后期处理提示词

```text
用代码做后期：
1. 转场：[哪一镜到哪一镜，用什么东西盖屏或带过去]。运动模糊切 8–16 份，半帧快门。
2. 调色：按故事分段。只调彩度和亮度，不动色相，强调色受保护，肤色不变。不加颗粒、柔光、暗角。
3. Seedance 的 mp4 按 BT.601 解码，中间文件用无损格式，交付标 BT.709。
4. 放大：720p 用 lanczos 放大到 1080p，加轻微锐化。不用整段插帧。
5. 按小节卡点：拍点只从原曲上测，不要在剪过的文件上测。
做完抽查切点前后 3 帧。
```

这是成片：[文件]。你第一次看，我不告诉你任何结论。
1. 全部解码，每镜取多张全分辨率帧，切点前后各取 3 帧。

### 三、进阶架构：四线程 Agent 协作模式

为了让 Claude Code / Codex 把“总导演”干得更稳，作者设计了 **1 主 + 3 子 Agent** 的四线程配合模式：

| 角色 | 职责说明 |
| --- | --- |
| **主做（Main）** | 主 Agent 本身，负责所有具体制作与工具调用 |
| **审核（Reviewer）** | 子 Agent，只挑错不改文件；每一步都查，提交视频生成前必须明确写“通过” |
| **监督（Supervisor）** | 子 Agent，读取用户说过的所有历史记录整理成要求清单，每一步盯着所有人（含主做）有没有遗忘要求 |
| **代理（Proxy）** | 子 Agent，读取用户历史记录整理成偏好画像；当主做与审核有分歧或需提交付费生成时，在总预算内替用户按偏好拍板并写明依据 |

#### 【Prompt 10】四线程协作启动提示词

```text
这支片子用四线程来做。你当主做，再开三个子 agent，四个一起配合，一直做到片子做完，或者账户欠费为止。
我说过的话在：[对话记录或者要求文件的路径；Claude Code 的记录在 ~/.claude/projects/ 下]。
总预算：¥[金额]。

分工：
- 主做：就是你，负责所有制作。
- 审核：开一个子 agent，只挑错，不改文件。每一步都要查，提交生成视频之前必须明确写“通过”。
- 监督：开一个子 agent，读完我说过的所有话，整理成要求清单。每一步都查有没有人忘了要求，包括你。
- 代理：开一个子 agent，读完我说过的所有话，整理成我的偏好。你和审核拿不准，或者要提交生成视频时，由它按我的偏好来决定，并写明依据和把握。它只能在总预算内批准提交，超过预算就停下来等我。

配合的顺序：
1. 你每做完一步，先交给审核，再交给监督。
2. 有分歧就交给代理决定。
3. 所有决定和花费都记进审核记录，我回来可以推翻任何决定。

不充值，不买额度。欠费就停，先把已有的片段粗剪出来给我看。
```

## 我的吸收判断

- **可复用能力（极高价值）**：
  1. **「先画尾帧，再改首帧 + 推镜靠裁切首帧 + 局部重绘贴回原图」**：这三条是解决多镜头首尾帧生视频时“背景微变导致墙面变色/物体蠕动”的实操金律。
  2. **代码辅助视觉预检**：在生图前先用 Python 生成 1920×1080 的 `38% / 62%` 黄金分割色块草图，并转成灰度图检查人物与背景的明暗反差；在生视频前把首尾帧叠片对比（查出杯子大小差 13% 这类肉眼易漏的漂移）。
  3. **针对 Seedance 模型的特定缺陷后处理代码化**：
     - `Seedance 2.5`：首帧过锐（直接裁掉第 1 帧）、尾帧跳变（取倒数几帧前正常画面定格）、写了无音乐仍混入 BGM（直接剥离音轨）。
     - `Seedance 2.0 mini`：视频越往后越暗越冷（每段视频以自身首帧为基准用代码做色彩匹配拉回）。
     - **色彩空间显式声明**：Seedance 输出 MP4 按 `BT.601` 解码，交付标 `BT.709`，避免平台上传后发灰或偏色。
  4. **四线程子代理架构（主做 + 盲审 + 监督 + 预算代理）**：特别是「盲审 Agent 绝不读取前序聊天记录，防止脑补」和「监督 Agent 扫描 `~/.claude/projects/` 历史会话提取用户红线清单」，可以直接迁移到 Hermes 的 `delegate_task` 多代理编排中。
- **值得沉淀到 skill / workflow 吗**：
  - **非常值得**。我们现有的视频管线（`video-common`、`stickman-omni-flash-pipeline`、`ai-showcase-remake-video`、`dashi-animationstyle`）目前在代码动画和口播上很成熟，但在**调用生成式视频模型（如火山 Seedance / MiniMax H3 / Veo）做首尾帧叙事短片**时，正好可以把这套「七段式视频提示词 + 首尾帧叠图盲审 Gate + Seedance BT.601/709 调色与首帧色偏校正脚本」吸收进视频制作技能库。
- **对 AI × Product × Super Individual 的价值**：
  - 这是典型的**把不确定性的抽卡变成确定性的工程流水线**范例。一人剧组（Super Individual）最大的成本黑洞不是 API 单价，而是“带着上游错误进入高单价视频渲染环节”。通过廉价的文本/视觉盲审 Agent 拦截 90% 的穿帮，单部短片的视频生成成本可以直接压缩 60%–80%。
- **风险或待验证点**：
  - **Codex 生图额度限制**：作者也提到 OpenAI 合并额度后，Codex CLI 生图很快会触发限额；在我们自己的工作流中，生图环节可灵活替换为 Gemini image / GPT-image-2（Dogbooks）或本地/API 图像模型，不必强绑 Codex CLI。
  - **Seedance 模型版本号**：文中提到的 `doubao-seedance-2-5-260628` 与 `doubao-seedance-2-0-mini-260615` 为火山方舟特定快照号，实际调用前需通过火山方舟控制台或 API 核对当前账号已开通的 Endpoint / Model ID。
