# Obsidian 创始人谈 Markdown 应用开发：让它更独特

## 核心观点

**"Weird isn't just visual. Weird is whatever strays from the norm."**

Obsidian 创始人 kepano 分享了他对 Markdown 应用开发的建议：**让它更独特（make it weirder）**。

## 什么是"独特"？

kepano 认为，独特性不仅仅是视觉层面的差异。真正的独特性包括：

- **偏离常规**：任何与当前主流做法不同的东西
- **相对概念**：独特性是相对于世界当前状态而言的
- **原则层面**：可以拥有独特的原则——那些人们可以合理分歧的观点

## 为什么 Obsidian 成功了？

kepano 提醒人们：**Obsidian 刚推出时非常独特（very weird）**。

这意味着：
1. 市场不会奖励"更安全"的选择
2. 成功的产品往往一开始看起来"怪异"
3. 独特性本身就是差异化优势

## .md 文件的本质

kepano 提出了一个关键概念：

> **".md is the Schelling point"**

（.md 是谢林点——一个人们自然汇聚的共识点）

这意味着：
- Markdown 格式已经成为知识工作者的通用语言
- 不是去创造新的格式，而是在现有 .md 基础上创新
- 市场真正需要的是**更多独特且多样化的与 .md 文件交互的方式**

## 对开发者的启示

如果你正在开发基于 Markdown 的应用：

| 不要这样做 | 要这样做 |
|-----------|---------|
| 做一个"更好的"传统笔记应用 | 创造一个全新的交互范式 |
| 遵循现有的 UX 模式 | 探索独特的交互方式 |
| 担心太独特会吓跑用户 | 记住 Obsidian 也曾被认为"怪异" |

## 延伸思考

这个建议不仅适用于 Markdown 应用：

1. **文件优先于应用**（File over app）—— 这是 kepano 的另一核心理念
2. **独特性与可移植性的平衡**—— 独特不代表封闭
3. **接受合理的分歧**—— 真正的独特性会引来争议，这才是健康的
