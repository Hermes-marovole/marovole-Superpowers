## 简介

Moxt 是一款面向组织和个人的 AI 工作空间产品，核心解决两个关键问题：Context（上下文）散乱在不同平台、以及非结构化数据对 AI 的"污染"。文章作者通过实际使用体验，展示了 Moxt 如何通过文件系统原生的 Workspace 设计、可累积的 AI 记忆、AI 同事系统、定时任务与 Webhook 自动化、以及 MCP 外部集成，构建一个完整的 AI 组织工作流。

## 详细内容

### 一、问题定义：Context 的「散」与「脏」

**核心洞察：**
> "Agent 能做到什么程度，不靠模型，靠你给它的工具和上下文。"

**问题现象：**
- **散**：工作 Context 分布在飞书、Notion、本地文件夹、微信聊天记录、大脑五个地方
- **脏**：不同格式需要"剥壳"——飞书的 block、Notion 的 toggle、PDF 的视觉排版、Slack 截图
- **切换成本**：切任务时一半时间花在搬运 Context

---

### 二、Moxt 的核心设计：AI 原生的工作空间

**解决方案：** 让 AI 在自己的"母语"和熟悉的环境中工作

#### 2.1 Markdown 是 AI 的母语

| 格式 | AI 处理效率 | 说明 |
|------|-------------|------|
| Markdown | ⭐⭐⭐⭐⭐ 秒懂 | AI 训练数据的主要格式 |
| Word | ⭐⭐☆☆☆ 需转换 | 本质是 Markdown 的 GUI，对 AI 是噪音 |
| PDF | ⭐⭐☆☆☆ 视觉排版干扰 | 需要额外解析层 |

> "Word 本质上就是 Markdown 的 GUI，那层 GUI 为人眼而设，对 AI 来说全是噪音。"

#### 2.2 自动格式转换

Moxt 的后台自动转换机制：

| 输入格式 | 转换为 | 用途 |
|----------|--------|------|
| Word/PDF/Notion | Markdown | AI 原生阅读 |
| Excel | CSV | 结构化数据处理 |
| 可视化报告 | HTML | 可直接预览的交付物 |

#### 2.3 文件系统是 AI 的图书馆

- **树状浏览**：AI 训练时熟悉的结构
- **grep 友好**：支持快速文本搜索
- **搬家爽点**：Claude Code 的 Skills（md 文件）可直接复制到 Moxt，零改造运行

### 三、AI 同事系统：从工具到分身

#### 3.1 默认 AI：momo

- 每个用户拥有一个专属个人 AI momo
- 行为规则写在 **AGENTS.md**，放在个人空间
- 类似 Claude Code 的 CLAUDE.md 思路，但产品化实现

#### 3.2 自定义 AI 同事示例：AI 藏师傅

作者创建的 AI 分身，基于歸藏的历史内容训练：

**输入材料：**
- 所有历史语录和写作内容
- agents.md、时间线等资料
- 语气风格文档

**生成的身份书包含：**
- 网名和平台矩阵
- 口头禅（「朋友们」「这太顶了」等）
- 感叹号用法规范
- 对话模式 vs 写稿模式的切换规则

**自动总结的 6 条核心信条：**

1. 没亲手用过就没有发言权
2. 松弛是生产力，不用数据审判自己
3. AI 是赋能工具，不是替代品
4. 开放生态 > 平台封闭
5. 只要敢花钱、敢放权，AI 就是许愿机
6. 朋友关系高于流量关系

#### 3.3 AI 同事的工作空间

每个 AI 同事拥有独立目录结构：

```
AI-Colleague/
├── drafts/          # 起草的内容
├── MEMORY.md        # 积累的偏好记忆
└── Skills/          # 可调用的技能
```

> "AI 的'记忆'不该是玄学，就是几个你能读懂的 md 文件而已。"

### 四、Skill 组合：复杂任务流水线

#### 4.1 公众号写作流水线示例

| 步骤 | Skill | 功能 |
|------|-------|------|
| Step 1 | humanizer-zh | 去除 AI 味 |
| Step 2 | writing-rewriter | 风格重写（小绿书/推特风格） |
| Step 3 | wechat-formatter | 公众号排版 |

**对比：**
- 以前：Claude Code 手动三步，每步复制粘贴
- 现在：丢入初稿，十几分钟拿到可直接发布的终稿
- 优势：所有中间版本在 Workspace 里，改动一目了然

### 五、定时任务：让信息来找你

#### 5.1 热点监控员示例

| 配置项 | 设置 |
|--------|------|
| 触发方式 | Cron 定时任务 |
| 执行频率 | 每天早上 |

### 六、Webhook：让事件来找 AI

#### 6.1 CodePilot 项目集成示例

| 场景 | 触发条件 | AI 处理 | 输出 |
|------|----------|---------|------|
| Bug 报告 | GitHub 新 Issue | 自动归类 | 归入「待修复」队列 |

| 用户问题 | GitHub 新 Issue | 内容分析 | 生成 FAQ 草稿 |

**价值：**
- 一个人没法 7×24 在线，AI 同事可以
- 先由 AI 筛选和预处理，再决定是否叫人类

**设计原则：** 不同文件夹有不同的权限控制

- 适用于组织架构中的信息隔离需求
- 安全性设计针对组织使用场景优化

### 八、MCP 集成：连接外部系统

#### 8.1 支持的 MCP 类型

| MCP | 查询示例 | 场景 |
|-----|----------|------|
| **Sentry MCP** | "最近线上有什么报错" | 运维监控 |
| **Figma MCP** | "设计稿里某个按钮的颜色" | 设计协作 |
| **Linear MCP** | "创建一个 bug ticket，优先级 high" | 项目管理 |

#### 8.2 组织场景价值

> "对于组织而言，经常需要从原来的 Notion 里查东西，或者从 Slack 去同步一些信息，这些流转过程都很重要。"

**对比个人 vs 组织使用：**
- 个人：MCP 主要用于单点查询
- 组织：MCP 用于跨系统信息流转与同步

### 十、核心理念：Agent 能力的乘法公式

**公式：**

```
Agent 能力 = 工具 × 上下文 × (人格 + Memory + Skill)
```

| 因子 | Moxt 提供的能力 |
|------|-----------------|
| **工具** | Sandbox、浏览器、Cron、Webhook、MCP、外部集成 |
| **上下文** | Workspace 累积的 md 文件 + 外部数据通道 |
| **人格 + Memory + Skill** | AGENTS.md、MEMORY.md、Skills/（均为可读写的纯文本） |

**关键洞察：**
> "这是个乘法。任何一个因子为 0，输出就是 0。模型再强也救不回来。"

### 十一、「一人公司」的重新定义

**核心信条：**
> "AI 是赋能工具，不是替代品"

**作者观点：**
> "一人公司里的'一人'，重点落在'决策和品味不被稀释'这几个字上，跟'一个人硬扛'没什么关系。"

**稀缺 vs 可替代：**

| 稀缺（人类保留） | 可替代（AI 接管） |
|------------------|-------------------|
| 判断 | Context 搬运 |
| 审美 | 任务切换 |
| 执念 | 重复性看一眼 |

**OPC（One Person Company）的真义：**
> "一个人的品味 × AI 同事的执行带宽，才是 OPC 真正的意思。"

## 适用场景

### 推荐阅读人群
- 一人公司/独立创作者
- 小型团队的技术负责人
- 内容创作者（周刊/博客/自媒体）
- 需要管理多个 Context 的知识工作者
- 探索 AI 组织工作流的团队

### 典型使用场景
1. **内容生产流水线**：从初稿到多平台发布的自动化
2. **信息监控与日报**：定时抓取多源信息并聚合
3. **项目自动化**：GitHub Issue 自动分类与响应
4. **AI 分身构建**：基于历史内容创建个人风格的 AI 同事
5. **跨系统数据整合**：通过 MCP 连接 Notion、Linear、Figma 等工具
