本文是小盖听完 DeepMind CEO Demis Hassabis 与 YC CEO Garry Tan 最新一期播客后的深度笔记整理。Demis 在访谈中分享了他对 AGI 发展现状的务实判断，指出当前大模型范式面临的三个关键瓶颈——持续学习、长程推理和记忆系统，同时也探讨了 AI 创造力的本质、小模型的独特价值，以及蒸馏技术如何重塑 AI 部署格局。

### 二、AGI 面临的三个关键问题

Demis 的态度非常明确：**现在的大模型范式（大规模预训练 + RLHF + CoT）一定会是 AGI 最终架构的一部分**，他不认为这是条死路。但要实现 AGI，还有三个关键问题要解决：

#### 2.1 问题一：Context Window 的暴力堆砌

现在大模型处理长信息最常用的做法是把 Context Window 一直撑大：
- 8k → 32k → 100 万 Token

**本质问题**：这本质上是**暴力堆砌**。Context Window 相当于人脑的工作记忆（Working Memory）。

**人类 vs 模型对比**：
- 人类工作记忆：约 7 个单元（心理学经典数字）
- 大模型工作记忆：已达 100 万 Token

**核心矛盾**：模型的工作记忆比人大几十万倍，但显然没有聪明几十万倍。

**问题的根源**：把所有东西都塞进 Context Window，里面包含了不重要的、错的、过时的东西——看起来信息很多，其实是一团乱麻。

**人类的解决方案**：人脑有另一套机制——**海马体**，负责把新知识整合进已有知识库。人在 REM 睡眠阶段，大脑会重放白天重要片段，让新东西温柔地融进旧知识体系。

**模型的缺失**：模型现在没有这套机制。每一次对话结束，刚学到的东西就会忘记。下次重新打开，还是上次那个模型，没长进。

---

#### 2.2 问题二：长程推理（Long-term Reasoning）

Demis 用国际象棋的案例来说明：

> 他喜欢跟 Gemini 下棋，因为能看到模型的 thinking trace（思考链）。
> 
> 有一次发现一件怪事：模型考虑一步棋时，思考链里清清楚楚写着这步是昏招。但接下来没找到更好的走法，于是**又走回这步昏招**。

**核心问题**：明明知道是错的，还是把错的那一步走出去了。

**暴露的缺陷**：模型缺少对自己思考过程的某种**内省能力**。正常人意识到一步是昏招后，脑子里会停一下、再想想——这个能力模型没有。

**长程推理的本质**：模型可以一步一步往前走，每一步看起来都合理，但走到后面整盘棋的方向其实是错的。它缺少那种退回到当前思考上一层、重新审视的能力。

---

#### 2.3 问题三：创造力与规则发明

Demis 反复提到了创造力，用两个例子对比说明：

**案例一：AlphaGo Move 37（2016 vs 李世石）**
- 局面：第二局走出举世震惊的一步棋
- 特点：所有人类几千年围棋经验都告诉它不该下那里
- 结果：下完之后发现是神来之笔
- **问题**：这只是 AI 创造力的起点吗？

**案例二：AI 能不能发明围棋本身？**
- 关键区别：Move 37 是在**既定规则内**创新；围棋的规则、棋盘形状、对弈方式是**人类发明的**
- **核心问题**：AI 在已有框架里很厉害，但能不能自己**造一个框架**？

**爱因斯坦测试**：
> 用 1901 年人类已有的全部知识训练模型，看它能不能在 1905 年推出狭义相对论。

爱因斯坦的 1905 奇迹年不是从已有论文拼接出来的，而是基于已有材料做了一次**全新的概念跳跃**。

**当前模型的局限**：
- 主要做两件事：pattern matching（找规律）和 extrapolation（延伸规律）
- 缺少：analogical reasoning（类比推理）——从一个领域抽出深层结构，搬到全新领域

### 三、小模型的独特价值

Demis 给出了一个**出乎意料的判断**：

> 未来 6-12 个月，真正的价值不在更大的模型，在**更小的模型**。

#### 3.1 为什么是小模型？

**直接好处**：
1. **成本** — 同样任务，小模型推理价格可能只有前沿模型的 1/10 甚至更少
2. **速度** — 比成本更重要的因素

**核心逻辑**：
> 当小模型能力已达前沿模型的 90%-95%（已经相当不错），剩下那 5%-10% 的能力差距，比不上速度带来的好处。

#### 3.2 速度的价值：心流与迭代

**工程师编程场景**：
- 现有节奏：想法冒出 → 几秒看到结果 → 不行就改 → 再不行再改
- 良性循环：一改再改的循环跑得越快，做出来的东西越好
- **关键阈值**：如果每次调用要等 10 秒，整个工作流就被打断

**心流的重要性**：
- 快到一定程度，工程师能进入心流：想法 → 尝试 → 反馈 → 想法，思维不被打断
- **结果差距**：进入心流 vs 频繁掉出心流，产出差距是**数量级**的

**Agent 场景**：
- 一个 Agent 跑完任务可能要调几十次模型
- 每次慢 1 秒 → 整个任务慢 1 分钟
- **临界点**：慢到一定程度，Agent 从"能用"变成"鸡肋"

#### 3.3 边缘部署与隐私

**小模型不是廉价替代品，有些事只有小模型能做**：

| 场景 | 需求 | 小模型优势 |
|------|------|-----------|
| 手机 | 本地实时处理 | 无需联网、低延迟 |
| 智能眼镜 | 看懂周围世界 | 实时视觉理解 |
| 家用机器人 | 听懂对话指令 | 隐私保护（数据不上云） |

**隐私作为底线**：
> 家里机器人看到的视频、听到的对话，全部在设备本地处理，根本不上云。这件事对很多用户来说不是加分项，是**底线**。

---

### 四、蒸馏技术：大模型到小模型的能力迁移

**Demis 的判断**：目前没看到信息密度有任何理论上限，小模型的智能天花板还远没看到。

**蒸馏的核心逻辑**：
1. 先训练一个超大模型
2. 用超大模型去教一个小模型
3. 教完后，小模型用极少参数复现原来 **95%+** 的能力

**为什么 DeepMind 重视蒸馏？**
> 要把 AI 能力放进谷歌的头部产品，前提是**低延迟、低成本**。前沿模型再强，每次推理花几秒钟、花几毛钱——这条路很难走得通。

**时间表**：
- 前沿模型发布后 **6-12 个月** 内
- 就能把能力蒸馏到边缘设备能跑的小模型上
- 比很多人想的要快

### 五、未来架构：大小模型协同

**端到端智能助手的架构构想**：

```
┌─────────────────────────────────────────────────────┐
│                  用户设备层                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐           │
│  │  智能眼镜 │  │ 家用机器人 │  │  手机助理 │           │
│  │  (小模型) │  │  (小模型) │  │  (小模型) │           │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘           │
│       │             │             │                │
│       └─────────────┼─────────────┘                │
│                     │                              │
│              本地处理 95% 日常任务                  │
│                     │                              │
│              ┌──────┴──────┐                      │
│              │ 复杂问题上云 │                      │
│              │   (触发)    │                      │
│              └──────┬──────┘                      │
│                     │                              │
└─────────────────────┼──────────────────────────────┘
                      │
              ┌───────▼────────┐
              │   云端前沿模型   │
              │  (大模型后援)   │
              │ 处理剩余 5%   │
              │ 复杂任务       │
              └────────────────┘
```

**协同逻辑**：
- **小模型在边缘做主力** — 处理绝大部分日常任务，本地跑、快响应、保隐私
- **前沿模型在云端做后援** — 只有特别复杂、本地搞不定的问题才发起请求

**对小模型的要求**：
- 不能只处理文字
- 必须能理解物理世界（视觉、音频）
- 这也是为什么 Gemini 从一开始就坚持**多模态**

## 关键概念速查

| 概念 | 解释 | 类比 |
|------|------|------|
| Context Window | 模型一次能处理的 Token 数量 | 人脑的工作记忆 |
| 海马体 | 大脑中把新知识整合进已有知识库的部分 | 模型的持续学习机制（缺失） |
| REM 睡眠 | 快速眼动睡眠，大脑重放白天片段进行学习 | 模型需要的"离线整合"阶段 |
| 长程推理 | 基于整体目标调整策略的推理能力 | 下棋时"停一下再想想" |
| 蒸馏 | 用大模型教小模型，保留 95%+ 能力 | 知识压缩与迁移 |
| 心流 | 专注状态下的高效工作模式 | 编程时的沉浸体验 |

## 值得关注的要点

### Demis 的核心判断
1. **当前范式不会死** — 预训练+RLHF+CoT 会是 AGI 最终架构的一部分
2. **小模型价值被低估** — 6-12 个月内真正的价值在小模型
3. **信息密度无上限** — 小模型的智能天花板还远未触及

### 小模型的三重价值
1. **成本** — 推理价格可能只有 1/10
2. **速度** — 进入心流、快速迭代的关键
3. **边缘部署** — 本地处理、隐私保护

### AGI 的三大鸿沟
1. **持续学习** — 如何把新知识温柔地融进旧知识体系
2. **长程推理** — 缺少对自己思考过程的内省能力
3. **创造力** — 能在规则内创新，但难以发明规则本身
